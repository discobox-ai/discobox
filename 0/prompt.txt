I found five built-in agent harnesses: claude-code, codex-cli, copilot, omp and opencode. There is also a `shell` harness, which runs no agent. Every agent CLI except Copilot has a way to push a message into the session that is already running in the terminal. Discobox uses none of these today. It reaches a running agent only by typing into its terminal (ADR 0137, `sandbox-agent/DESIGN.md:926-934`). The only opencode code it has is a plugin that publishes lifecycle events out of opencode.

**What this means for building it:**
- **Two harnesses could do this from code Discobox already ships inside the agent:** the opencode plugin (`harness/opencode/hook-plugin/server.js`, using the server's own client) and the omp extension (`harness/omp/hook-extension.js`, using `pi.sendUserMessage`). Both run inside the agent process, so neither needs a port or extra auth.
- **Codex** needs nothing added to the image: running `codex queue` in the sandbox should reach the live TUI.
- **Claude Code** needs a channel MCP server in a plugin. Because of the preview allowlist, a custom one only loads via `--dangerously-load-development-channels` or a managed `allowedChannelPlugins`. It also doesn't work for Bedrock, Google Cloud or Foundry users, and Team/Enterprise orgs need `channelsEnabled`.
- **Copilot** has no supported local way in. Typing into the terminal (ADR 0137) stays the only option unless extension `session.send` turns out to work.</result>
