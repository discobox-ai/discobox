Hidden commands/flags and user-declared tools are intentionally omitted. Aliases name the same command.
Flags below include inherited global flags. Defaults are the built-in defaults;
environment and configuration can override them.

[Concepts](concepts.md#providers-and-pools). They are not static CLI definitions.

## discobox admin audit dns

~~~~text
List the DNS lookups discoboxes made, newest first, from every pool in the
project. With --follow, print the last --limit oldest first and keep printing
lookups as they are recorded.

A discobox resolves the names Docker cannot answer by asking its pool, over the
same mTLS identity its HTTP uses, and the pool records each lookup: the name and
type asked, the response code, and the addresses and names that came back. A
lookup that got no answer says why instead. The pool records these, so a
discobox cannot alter them.

The trail is complete only up to a budget per discobox, of about 50 lookups a
second with bursts of 500. Past it the pool keeps answering but stops
recording, so a discobox that spends the budget first can make lookups this
list does not show, and nothing here says when that happened.

Requests made through the proxy do not appear here: the proxy resolves those
names itself. What appears is what software in the discobox resolved on its
own.

A lookup lives on the pool that answered it for the audit retention window,
after the discobox is gone. A pool that cannot be read is named on stderr (and
under unavailablePools with -o json), and its lookups are missing from the
list.

The name is what the discobox asked, and is shown as data, with non-printing
characters escaped.
~~~~

```text
discobox admin audit dns [flags]
```

Examples:

```text
  discobox admin audit dns --discobox sbx_1 --since 1h
  discobox admin audit dns --name api.github.com --follow
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| --color | WHEN | auto | set color &#96;WHEN&#96; to auto, always, or never |
| --debug | bool | false | print HTTP requests and the git commands run on this machine Value when passed without an argument: true. |
| --discobox | string |  | Only this discobox's lookups; a deleted one needs its full ID |
| --follow, -f | bool | false | Keep printing lookups as they are recorded Value when passed without an argument: true. |
| --help, -h | bool | false | help for dns Value when passed without an argument: true. |
| --limit | int | 1000 | Maximum number of lookups to return |
| --name | string |  | Only lookups of this name |
| --output, -o | string | table | output &#96;FORMAT&#96;: table or json |
| --pool | string |  | Only lookups answered by this pool |
| --server | string |  | connect to &#96;SERVER&#96;, an endpoint or a registered server's name; defaults to the primary "discobox admin remote primary" set, and to the local server when none is |
| --since | duration&#124;time |  | Only lookups from this long ago (e.g. 1h) or since this RFC 3339 time |
| --token | string |  | bearer &#96;TOKEN&#96; for API requests |

## discobox admin audit get

~~~~text
Print everything recorded about one audit record, by the ID "audit ls"
reports for it.

The ID says which trail to read: http_<row> is an exchange the pool's proxy
recorded, dns_<row> a lookup the pool answered, sreq_… an ask for a new value
of a token and how it was answered, and evt_…
either a harness hook or an exec event, both of which the discobox keeps inside
itself.

An http record's headers are shown as the proxy stored them, which is already
redacted: a credential the proxy swapped into the request was never written to
the row. Its body and any upgraded stream are not printed here, because they
are unbounded bytes; the record says which were recorded, and
"audit http --body <id>" prints them.

Every value a discobox wrote is shown as data, with non-printing characters
escaped.
~~~~

```text
discobox admin audit get DISCOBOX RECORD_ID [flags]
```

Examples:

```text
  discobox admin audit get sbx_1 http_10219
  discobox admin audit get sbx_1 sreq_k4m2p9x7q1w8r3t5
```

| --help, -h | bool | false | help for get Value when passed without an argument: true. |

## discobox admin audit http

~~~~text
List the HTTP requests discoboxes made through their pool's proxy, newest
first, from every pool in the project. With --follow, print the last --limit
oldest first and keep printing requests as they are recorded.

The proxy records these from what crossed the wire, so a discobox cannot alter
them. SECRETS names every secret whose value the proxy swapped into a
request, however it reached the discobox — a harness's own keys included. A
request recorded by a pool from before secrets were recorded names none.

--body ID prints what the proxy recorded beside the request with that ID: the
response body, or with --part the request body or an upgraded connection's
stream. Recorded bytes are written as they are when stdout is not a terminal,
and with non-printing characters escaped when it is. "audit get" prints the
rest of what was recorded about one request.

A request lives on the pool that proxied it for the audit retention window,
after the discobox is gone. A pool that cannot be read is named on stderr
(and under unavailablePools with -o json), and its requests are missing from
the list.

The method, URL and host are what the discobox sent, and are shown as data,
with non-printing characters escaped.
~~~~

```text
discobox admin audit http [flags]
```

Examples:

```text
  discobox admin audit http --discobox sbx_1 --status 4xx
  discobox admin audit http --blocked --follow
  discobox admin audit http --discobox sbx_1 --body http_42 > response.json
```

## discobox admin audit ls

~~~~text
List everything recorded about one discobox as one timeline, newest first.
With --follow, print the last --limit oldest first and keep printing records as
they are recorded.

SOURCE says which trail a record came from, and that is also what says how much
it is worth:

  http   the pool's proxy recorded the request from what crossed the wire. The
         discobox cannot alter it.
  dns    the pool recorded a name the discobox looked up, and what came back.
         The discobox cannot alter it. Read only when --source names it:
         lookups outnumber everything else.
  refresh
         the server asked for a new value of a token this discobox needed,
         and recorded who answered and when. How the value was made is the
         answering client's word: its record is marked "client" with -o json.
  hooks  what the coding harness published inside the discobox.
  execs  what the discobox recorded about its own execs.

The hooks and execs trails are kept inside the discobox, where anything running
in it can rewrite them, and can be read only while it runs. A trail that could
not be read is named on stderr (and under unavailable with -o json); its records
are missing from the timeline.
~~~~

```text
discobox admin audit ls [DISCOBOX] [flags]
```

Aliases: list.


## discobox admin binding create

~~~~text
Create a secret binding, as the API takes one: a secret by name or ID, a
target kind (project, harnessConfig or sandbox) and, for any but the project, its
ID. --as names the variable a use binding is delivered in, and --raw hands over
the value itself there (env) or a file holding it (file) rather than a
sentinel; --delegate makes it a binding to give on, and --use=false one only
given on. --route narrows the
secret's routes for this binding; left out, it goes where the secret's go.

A route is [METHODS ]HOSTS[PATHS][ graphql=OPS[:FIELDS]][ mcp=TOOLS][=blocked],
one per --route:

  METHODS   upper-case methods joined by commas (GET,HEAD); left out, any
  HOSTS     hosts joined by commas. A host is exact: *.example.com is every
            host beneath example.com but not example.com itself, and * alone
            is any host. A :port is dropped, so a host is every port of it
  PATHS     from the first /, several joined by ,/ (api.github.com/a/**,/b).
            A path is matched whole, a segment at a time and ignoring case:
            * is one segment, ** (last only) any number, so /repos/acme is
            that one path and /repos/acme/** it and everything beneath it.
            Left out, any path
  graphql=  the GraphQL operations allowed (query, mutation, subscription, or
            * for any), then optionally :FIELDS, the root fields they may
            select, each name allowed one trailing *
  mcp=      the MCP tools a tools/call may name, or * for any
  =blocked  refuses what the route is the most specific route for: a
            carve-out inside a wider route

  '*'
  api.github.com
  'GET api.github.com/repos/*/*/pulls/**'
  'api.github.com/graphql graphql=mutation:createPullRequest'
  'api.github.com/repos/*/*/pulls/*/merge=blocked'

A request must fall on a route of every list it is held to; within a list the
most specific route it falls on decides, host first, then path.
~~~~

```text
discobox admin binding create --secret SECRET --target-kind KIND [--target ID] [--as VAR] [--raw env|file] [--delegate] [flags]
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| --as | string |  | The variable a use binding is delivered in |
| --color | WHEN | auto | set color &#96;WHEN&#96; to auto, always, or never |
| --debug | bool | false | print HTTP requests and the git commands run on this machine Value when passed without an argument: true. |
| --delegate | bool | false | Let the target give it to the discoboxes it leads Value when passed without an argument: true. |
| --for | duration |  | How long it lasts (e.g. 1h, 2w, forever); the secret's limit when omitted |
| --help, -h | bool | false | help for create Value when passed without an argument: true. |
| --output, -o | string | table | output &#96;FORMAT&#96;: table or json |
| --policy | FILE |  | A credential policy FILE; repeat to merge routes. Following --policy-arg flags belong to this file |
| --policy-arg | NAME=VALUE |  | An argument NAME=VALUE for the preceding --policy; repeat for more |
| --raw | delivery |  | Hand over the value itself: env, or file for a file whose path is in the variable; left out, a sentinel |
| --route | stringArray | [] | A route narrowing the secret's, as [METHODS ]HOSTS[PATHS][ graphql=OPS[:FIELDS]][ mcp=TOOLS][=blocked]; one per flag, repeat for more |
| --secret | string |  | The secret, by name or ID |
| --server | string |  | connect to &#96;SERVER&#96;, an endpoint or a registered server's name; defaults to the primary "discobox admin remote primary" set, and to the local server when none is |
| --target | string |  | The harness config or discobox, by name or ID; omitted for the project |
| --target-kind | string |  | What it is bound to: project, harnessConfig or sandbox |
| --token | string |  | bearer &#96;TOKEN&#96; for API requests |
| --use | bool | true | Deliver it to use (default true unless --delegate) Value when passed without an argument: true. |

## discobox admin binding update

~~~~text
Change a secret binding by ID. --route replaces its routes, and --clear-route
removes them, so it goes where its secret's go.

A route is [METHODS ]HOSTS[PATHS][ graphql=OPS[:FIELDS]][ mcp=TOOLS][=blocked],
one per --route:

  METHODS   upper-case methods joined by commas (GET,HEAD); left out, any
~~~~

## discobox admin box export

~~~~text
Write a discobox to a .dbox archive that can be imported on another server.
~~~~

## discobox admin box update

~~~~text
Update a discobox.

--harness selects a harness by slug, name or ID. Stop the discobox
first; the update leaves it stopped. The new harness provisions on its next start.
Conversation state is not transferred between harnesses.

--egress-allow, --egress-deny-by-default and --egress-passthrough set the
discobox's own egress level, which it converges onto while running. Run from a
discobox, an update may change only --egress-passthrough of a discobox it
created, and only to hosts its own passthrough covers.

--discobox-api lets the discobox call the discobox API through its pool, in the
sandbox role, acting only on the discoboxes it leads; --discobox-api=false
takes that away. It is a person's to change.

Egress is decided per discobox from four levels: its project, its pool, its
harness, and its own. A discobox is restricted when any level sets
--egress-deny-by-default, and then reaches only the union of every level's
--egress-allow entries and the hosts its harness image declares; an allow list
alone restricts nothing. An entry is a host ("github.com" is that host alone),
a wildcard ("*.github.com", "registry.*", "*"), an IP, or a CIDR, never a port.
--egress-allow replaces this level's list; on an update, --clear-egress-allow
empties it.

--egress-passthrough names hosts whose HTTPS proxy CONNECT is spliced to the
origin unread instead of intercepted, so TLS stays end to end: for a client that pins its certificate, or a protocol the proxy
does not read. It never admits a host, and nothing inside such a tunnel is read:
no credential is swapped into it, and only the connection, its TLS hello, and
its byte counts are audited. A discobox a person creates passes through every
level's hosts; one a discobox created, only its own level's, which a discobox
may set only to hosts its own passthrough covers. On an update,
--clear-egress-passthrough empties this level's list.
~~~~

```text
discobox admin box update DISCOBOX [flags]
```

## discobox admin harness update

~~~~text
Update a harness config.

--egress-allow, --egress-deny-by-default and --egress-passthrough set the
harness's egress level, which every discobox on the harness converges onto,
running ones included. The hosts the harness bundle declares (imageEgressHosts)
are part of this level already and need not be listed.

Egress is decided per discobox from four levels: its project, its pool, its
harness, and its own. A discobox is restricted when any level sets
--egress-deny-by-default, and then reaches only the union of every level's
--egress-allow entries and the hosts its harness image declares; an allow list

empties it.

origin unread instead of intercepted, so TLS stays end to end: for a client that pins its certificate, or a protocol the proxy
does not read. It never admits a host, and nothing inside such a tunnel is read:
no credential is swapped into it, and only the connection, its TLS hello, and
its byte counts are audited. A discobox a person creates passes through every
level's hosts; one a discobox created, only its own level's, which a discobox
may set only to hosts its own passthrough covers. On an update,
~~~~

## discobox admin pool console

~~~~text
Open an administrative console on the machine hosting a pool's runtime.

The console is a privileged container in the pool host's PID, IPC, network,
UTS, and cgroup namespaces, running as root with the host filesystem at /host
and the host's Docker socket in place. It runs the pool image, so docker, git,
and curl are already there.

It is meant for debugging a backend — a WSL or macOS VM that will not boot
Docker, an agent that never registers — and reaches the host through the
provider driver rather than through the pool agent, so it still answers when
the agent does not.

A vm pool has no such container: on a remote driver the console is a login shell
in the pool's machine, and on a local one there is none to open, because the
pool agent runs on this machine itself — read its log with "discobox admin pool
logs" instead.

One console container is kept per pool host and reattached, so a capture or a
~~~~

## discobox admin pool resources

~~~~text
Show what a pool and its discoboxes are consuming.

CPU is reported in vCPU-equivalents: 1.00 is one core saturated, 3.70 is 3.7
cores' worth. The figure is a rate the pool agent computed by differencing
cumulative counters across one tick, so every discobox in the pool was measured
over the same window and the column both ranks and sums.

The overhead line is the load that is no discobox: the pool agent itself, the
shared BuildKit builder, the pool registry, and the proxy all run in the pool
container. A pool that looks busy with idle discoboxes usually has a build in
flight.

host bills the discobox, including page cache; RESIDENT is what its processes
~~~~


## discobox admin remote

~~~~text
List and manage the servers this client lists discoboxes from.

There is always a primary server: the one --server names, else the one
"discobox admin remote primary" chose, else the local one. Discoboxes are
created there unless you choose otherwise, and it is the only one started for
you.

Registered servers are listed beside it. "discobox ls" and "discobox console" list
every server's discoboxes, a command given a discobox ID finds it on whichever
server has it, and the console's run options can create one on any of them.
--server takes a registered server's name as well as an address.

A server's address is one of:

  discobox://<peer-id>        a peer, reached over iroh
  discobox://<host>:<port>    an https server, by IP or name
  discobox://<host>           a peer when a _discobox.<host> TXT record names
                              one, and an https server when none does
  discobox+http://<host>:<port>   a plain-http server, said outright

A discobox's address is its server's with the discobox after it,
discobox://<server>/<discobox>. Attaching to one registers the server it names.
discobox:///<discobox>, with no server, is a discobox on the primary server.

With no subcommand, this lists the servers.
~~~~

```text
discobox admin remote [flags]
```

Aliases: remotes.

Examples:

```text
  discobox admin remote
  discobox admin remote add discobox://box.example.com
  discobox admin remote add discobox://10.0.0.5:8443 --name lab
  discobox admin remote rename lab workstation
  discobox admin remote primary workstation
  discobox admin remote rm workstation
```

## discobox admin server stage

~~~~text

A release CLI carries a description of the server it was cut against — where
each of its files lives and what each one's SHA-256 is — and this turns that
~~~~

## discobox admin ssh-config

~~~~text
Emit ssh_config(5) Host stanzas — one per discobox in the current project — plus
the server's known_hosts line, suitable for `discobox admin ssh-config >> ~/.ssh/config`
or an ssh_config Include directive.

With --write, the stanzas and the server's host key are written to files this
command owns and rewrites, and ~/.ssh/config gains a single Include line pointing
at them. Nothing else in ~/.ssh is edited.

--write covers every server: the primary and the ones `discobox admin remote`
lists, each into its own files. Without it, the stanzas printed are the
primary's, since what is printed is one block to paste; --server picks another.

On WSL that happens twice, once for each of the machine's two ssh installations:
this distribution's, and the Windows one that a Windows VS Code or JetBrains
Gateway drives. Without --write, the printed stanzas are this side's.

SSH ingress over the same endpoint every other request uses, which is the only way
in: the server binds no SSH port of its own. So ssh — and anything built on it,
such as VS Code Remote-SSH — connects wherever this CLI does.
~~~~

## discobox admin terminal wait

~~~~text
Block until one of the conditions given holds, and say which: a harness hook
event (--hook), no output or input for a while (--idle), or the terminal's
program exiting (--exit). It is one wait, held at most 60s.

A hook event may be named either as the harness emits it or by its canonical
(Claude Code) name, so --hook Stop ends on any harness with a turn-end hook,
and the event printed back is the canonical one wherever the hook has one. An
event with no canonical name is named, both ways, as its harness names it; JSON
output carries both names.

It prints the reason — hook (with the event and hook ID), quiet, or exit — and
exits 0, or prints timeout and exits 124. The last field is where the next
wait resumes: pass it as --after, as input's output is passed, and a hook
recorded between two calls is not missed. --after is also where --idle counts
from: a terminal quiet since that point, by --idle's length, answers at once.
Without --after, only hooks recorded after the wait began count, and quiet is
counted from it. Pass "primary" for the discobox's harness
terminal.
~~~~

```text
discobox admin terminal wait DISCOBOX TERMINAL_ID [flags]
```

Examples:

```text
  after=$(discobox admin terminal input sbx_1 primary "run the tests" Enter)
  discobox admin terminal wait sbx_1 primary --hook Stop --after "$after"
  discobox admin terminal wait sbx_1 primary --idle 10s --exit
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| --after | string |  | Count only hooks recorded, and quiet, after this resume point, as input or a previous wait printed it |
| --color | WHEN | auto | set color &#96;WHEN&#96; to auto, always, or never |
| --debug | bool | false | print HTTP requests and the git commands run on this machine Value when passed without an argument: true. |
| --exit | bool | false | Wait for the terminal's program to exit Value when passed without an argument: true. |
| --help, -h | bool | false | help for wait Value when passed without an argument: true. |
| --hook | stringSlice | [] | Harness hook event to wait for, by its own or canonical name, such as Stop (repeatable) |
| --idle | duration | 0s | Wait for no output or input for this long (e.g. 10s) |
| --output, -o | string | table | output &#96;FORMAT&#96;: table or json |
| --server | string |  | connect to &#96;SERVER&#96;, an endpoint or a registered server's name; defaults to the primary "discobox admin remote primary" set, and to the local server when none is |
| --timeout | duration | 1m0s | Give up after this long, at most 60s |
| --token | string |  | bearer &#96;TOKEN&#96; for API requests |

## discobox adopt

~~~~text
Ask a person to let this discobox lead DISCOBOX, and wait for their answer.

Run this inside a discobox with discobox API access (--discobox-api at creation).
A person approves or denies the request in the console's inbox on the secrets
screen (F4), or from the requester's row (C). --reason is required and is shown
to that person. Ctrl-C stops waiting; the request stays in the inbox.

Approval replaces the child's current parent. The child's credentials and
creator stay its own. The parent may run commands and login shells, read and
write files, and attach to or end existing execs. This may expose existing files
and credential sentinels. A child with wider egress can only be read: writes and
sends into it are refused. The child must be in the same project, cannot be
this discobox or an ancestor, and cannot be archived or deleting.

Use "discobox release" to give a child back and "discobox ls --parent me" to
list the discoboxes this one leads.
~~~~

```text
discobox adopt DISCOBOX [flags]
```

```text
  discobox adopt mybox --reason 'Carry this feature through review'
```

## discobox push

~~~~text
Send this machine's commits to the pool a discobox fetches from.

Commits only ever move local -> the discobox's pool. Nothing in the discobox
moves: no branch of its own changes, nothing is rebased, nothing is checked out.
Inside the discobox the pool is the remote named discobox, and the new commits
show up as discobox/<branch>, to be picked up whenever the work there is ready
for them:

    git fetch discobox && git rebase discobox/<branch>

The discobox's origin is the source's own remote, and a push here does not
touch it. (In a discobox created before 26-10-10-545 the pool is origin, and
the remote is upstream; push prints the command for the discobox it pushed to.)

Without DISCOBOX the discobox is taken from the ones "discobox ls" shows: the
only one when there is one, otherwise you are asked to pick.

This applies to each source that came from a directory on a machine. Every
such source of the discobox is pushed; --source narrows to one, named by its
slug. A source that is a remote URL has no checkout to push from: the discobox
fetches that remote itself, there is nothing to send, and push says so.

For each source, the branch it was created from is pushed by default. --branch pushes a
different local branch instead, landing under its own name, which the discobox
then sees as discobox/<that branch> — useful for offering it a branch to rebase
onto or cherry-pick from without touching the one it tracks.

Uncommitted changes are never pushed; only commits. They are reported so it is
clear what stayed behind.

A discobox that is still waiting for its source -- one whose create failed after
it had been provisioned -- is delivered rather than offered something to rebase
onto: every source it waits for is pushed at the commit it was created from,
with any uncommitted work that create captured, and reported complete, which
starts it. That needs the repositories those sources came from to still hold

the time there is nothing to run here. This command is what covers the rest: a

A push may rewind the discobox's origin — that is what a local rebase or amend
means — but not silently: it is refused if the origin has moved since this
machine last pushed, or if it holds commits this machine did not put there.

holds.
~~~~

## discobox run

~~~~text
Launch a prompt in a new discobox cut from SOURCE.

SOURCE is the first argument: a directory (. for this one), a repository URL, or
GitHub OWNER/REPO, then optionally @REF and //PATH, the directory inside it the
harness starts in. The prompt is the words after it, or -p to give it as one
argument. Use -- when the words need to be separated from command flags
explicitly. This is the only command that makes a discobox: the bare "discobox"
takes no prompt and none of these flags.

Use - as the entire prompt to write it without shell escaping. At a terminal,
it opens a multiline composer: Enter submits, Shift-Enter adds a newline, Esc or
Ctrl-C cancels, and Alt-E opens $VISUAL/$EDITOR. With piped stdin, - reads the
prompt from stdin instead. An empty or whitespace-only prompt cancels the run.
Esc asks for confirmation before discarding a nonempty prompt.

By default run opens the console's window and makes the discobox there: a
question still open — where to cut from, whether to copy a directory in no
repository — is asked on it, the wait is drawn on it, and
what it lands on is the discobox itself — its default terminal (the configured
harness, or a shell when it has none), the shells and services running beside
it, and its forwarded ports. It is the same screen, in the same window, that
typing the same thing into "discobox console" gives you. Press Ctrl-A d to leave,
which detaches and exits; the discobox and everything in it keeps running
(DISCOBOX_LEADER changes the Ctrl-A).

--raw creates the discobox here instead and attaches this terminal to its
default terminal: the stream and nothing else, for a pipe, a recording, or a
terminal you would rather keep as it is. The questions are asked on this
terminal, one per source. Ctrl-A d detaches there too. If an interrupt stops
getting through — the discobox or the server has gone quiet — Ctrl-C again says
so, and one more quits, leaving the terminal running like a detach. Without a
terminal to draw a window on, run is raw whether or not the flag was given.

Pass -d to create the discobox and print it without attaching at all; there is
no window in that either.

With no arguments at all (and no --no-source), run asks where to cut the
discobox from. In the window that is the same card Enter in the console opens,
with every other flag given already filled in; with -d or --raw it is an inline
picker. This directory is the first choice either way, and Esc creates nothing.
Without a terminal there is nobody to ask, and SOURCE is required.

Only committed history goes in by default: the discobox starts from the commit
checked out in SOURCE, and uncommitted changes there are left behind, with a
warning naming how many. --include-dirty carries them in as a snapshot on top of
that commit.

The source keeps its own path inside the discobox, so /home/you/src/app is
/home/you/src/app in there too. That holds for a directory under /home, /Users,
/mnt, /workspace, /Volumes, /media, /srv, /opt, /data or /var/home; everywhere
else the discobox's own system owns the path, so the source is placed at
/workspace/source instead and the discobox starts in the same subdirectory you
ran from. A source at one of those roots itself, or under /opt/discobox, is
placed that way too.

A source directory that is not in a Git repository works too: everything in it
is carried into the discobox as uncommitted changes on an empty first commit,
and nothing is written to the directory itself. There is no commit to start
from instead, so --include-dirty does not decide this one: at a terminal run
asks first, with the size it would copy counted while the question is on screen,
and copying is the default answer. Declining still creates the discobox, with
nothing checked out in it, exactly as --no-source does. Without a terminal the
directory is copied.

--no-source creates a discobox with nothing checked out in it, for work that
starts from an empty machine rather than from a repository. It takes SOURCE's
place, so every argument is the prompt. The directory you run in is still what
the discobox is filed under, so it is listed here like any other, and the Git
authorship it commits under is still read from here; only the source is left
out. -i still brings sources in, so --no-source -i ../foo is a discobox holding
foo and nothing else.

-i brings extra sources into the same discobox, repeat it for more than one. Each
is resolved exactly like SOURCE is, --include-dirty included,
and a local one keeps its own absolute path inside the discobox, so ../foo shows
up at the path readlink -f ../foo prints, under the same rule the source
directory follows above; one from anywhere else is placed under /workspace,
named after itself.

A repository can name the others it is worked on with, in .discobox/settings.json
at its root:

  {"sources": {"foo": "https://github.com/acme/foo"}}

Each is brought in the way -i would: the ../foo you already have checked out
when there is one, and a clone of the URL when there is not. Either way it lands
beside the source -- at the same path when the source kept its own, under
/workspace when it did not -- so ../foo means the same thing inside the
discobox as it does here. --declared-sources=false leaves them out.

--skills DIR installs skills in the discobox: every subdirectory of DIR that
holds a SKILL.md is one skill, named after it, and is copied into the harness's
skill directories on its first launch. Repeat it for more than one directory.
--user-skills does the same with your own ~/.claude/skills and
~/.agents/skills, read before any --skills. A skill of the same name in a later
directory replaces the earlier one, and a discobox's skills replace the image's
and the repository's of the same name. Links are followed and .git is left
out; the skills are carried in the request, at most 1 MiB in all.

--skills URL[@REF][//PATH] is a Git repository instead: it is checked out under
~/.discobox/skill-sources in the discobox, and every subdirectory of PATH
(the repository's root without one) that holds a SKILL.md is linked into the
skill directories, not copied, so an edit to a skill lands in the checkout and
can be committed and pushed back. Several --skills naming one repository at one
ref share its checkout. A linked skill replaces a copied one of the same name,
whatever order they were given in.

Either can be made the default for every new discobox, in the console too, in
client.yaml under <XDG config home>/discobox (or wherever
DISCOBOX_CLIENT_CONFIG_FILE names): run.skills and run.userSkills. When
that variable is unset and <XDG config home>/discobox holds no client.yaml,
the client writes client.example.yaml there, listing every setting. --skills
given replaces run.skills rather than adding to it, and --user-skills=false
turns run.userSkills off.

-s stores a secret of its own and binds it as KEY, read from where it already
is: KEY takes $KEY from this shell, KEY=@FILE reads FILE (one trailing newline
dropped). KEY=VALUE takes the value itself, which then sits in shell history
and the process list. It is sent anywhere unless @HOST follows: KEY@HOST,
KEY=@FILE@HOST, KEY=VALUE@HOST send it to HOST alone, which is exact ('*.HOST'
for the hosts beneath it).

--bind binds a project secret to the new discobox, SECRET[:VAR][@ROUTE,...]:
the discobox receives a sentinel in VAR — the secret's name upper-snaked when
left out, so github is GITHUB — which its pool swaps for the value where the
secret's routes allow, narrowed by any ROUTE given — each a host, exact,
'*.suffix' for the hosts beneath suffix or '*' for any, optionally =blocked —
as Copilot CLI's GitHub token is:
'github:COPILOT_GITHUB_TOKEN@api.github.com,*.githubcopilot.com'. Policy files supply reusable routes, with their own arguments:
--bind 'github,policy=issues.json,owner=acme,repo=widget'. Repeat policy=FILE
within one binding to merge routes; each following NAME=VALUE belongs to
that file. Policy files and inline @ROUTE values are mutually exclusive. A route
with methods, paths or a protocol is also bound with 'discobox secret bind
--route'. --delegate
SECRET[@ROUTE,...] lets the new discobox give the secret to the discoboxes it
creates instead. In --from-json, "bindings" lists them. A discobox creating one
binds only what it may delegate, and delegates nothing.

--discobox-api lets the new discobox call the discobox API through its pool,
acting only on the discoboxes it leads. A discobox creating one may set it
only when it has it itself.

--from-json reads the whole request from stdin as one JSON object instead,
creates the discobox without attaching, and prints it as JSON. It is for a
caller that would rather not quote a prompt through a shell — an agent in a
discobox making another, above all. "source" is SOURCE, required
unless "noSource" is set; every other field is optional, and each means what
its flag does. No argument or other run flag may be given beside it:

  {
    "source": "https://github.com/org/repo",
    "prompt": "fix the failing tests in pkg/foo",
    "harness": "codex",
    "bindings": [
      {"secret": "npm", "envVar": "NPM_TOKEN", "routes": ["registry.npmjs.org"]},
      {"secret": "github", "delegate": true}
    ],
    "discoboxApi": false,
    "env": ["MODE=test"],
    "secrets": ["OPENAI_API_KEY=sk-...@api.openai.com"],
    "include": ["../foo"],
    "skills": ["./team-skills"],
    "userSkills": true,
    "noSource": false,
    "includeDirty": true,
    "declaredSources": true
  }
~~~~


## discobox secret bind

~~~~text
Give a secret to a discobox, every discobox on a harness config (--harness),
or every discobox of the project (--project-wide).

--as names the environment variable it is delivered in: a sentinel that the
discobox's pool exchanges for the value on the way out. It is never exchanged
on a host the discobox's egress passes through unread (--egress-passthrough): the proxy reads nothing inside such a tunnel, so the host
gets the sentinel and refuses it. Left out, it is the
secret's name upper-snaked: github is GITHUB, npm-token is NPM_TOKEN. --route narrows where it
may be sent for this binding; left out, it goes where the secret's routes say. --for is how long the binding lasts, within
the secret's limit.

--raw hands over the value itself rather than a sentinel, for a program that
signs with it or sends it where an exchange cannot reach: env puts it in the
variable, file puts there the path of a file under /run/discobox/raw-secrets
holding it. The secret must allow it (secret update --allow-raw). The value is
held in memory, never on a disk, and the pool refuses a request carrying it
off its routes, except on a host the discobox passes through unread, where it
is not looked for; and a discobox holding a value can send it anywhere, so that
is a guard against mistakes, not a boundary.

--policy FILE supplies reusable routes instead of --route. Repeat it to merge
policies into one route list; --policy-arg NAME=VALUE applies to the preceding
file. Arguments and defaults resolve locally and the binding stores concrete
routes. Editing a file does not change an existing binding. Blocked routes
participate across the merged list under the usual specificity rules.

--delegate lets the discobox give the secret, to use, to the discoboxes it
leads: by answering their requests, binding directly, or when it creates them. With --as as
well, it uses the secret too; without, it is delivered nothing itself.

For one discobox and one variable, the narrowest binding wins: a discobox's own
over its harness config's, and that over the project's.

A route is [METHODS ]HOSTS[PATHS][ graphql=OPS[:FIELDS]][ mcp=TOOLS][=blocked],
one per --route:

  METHODS   upper-case methods joined by commas (GET,HEAD); left out, any
  HOSTS     hosts joined by commas. A host is exact: *.example.com is every
            host beneath example.com but not example.com itself, and * alone
            is any host. A :port is dropped, so a host is every port of it
  PATHS     from the first /, several joined by ,/ (api.github.com/a/**,/b).
            A path is matched whole, a segment at a time and ignoring case:
            * is one segment, ** (last only) any number, so /repos/acme is
            that one path and /repos/acme/** it and everything beneath it.
            Left out, any path
  graphql=  the GraphQL operations allowed (query, mutation, subscription, or
            * for any), then optionally :FIELDS, the root fields they may
            select, each name allowed one trailing *
~~~~

## discobox tools

~~~~text
Run a development tool against a discobox.

DISCOBOX is the NAME "discobox ls" prints, an ID, or a short prefix of one.
Without it the discobox is taken from the ones "discobox ls" shows: the only one
when there is one, otherwise you are asked to pick. The tool's own arguments follow DISCOBOX, with an optional -- separator.
CLI flags go before DISCOBOX.

git runs inside the discobox and ssh opens a session to it. Every other tool is
declared in a file, and "discobox tools ls" lists the ones a discobox offers.
A tool runs either in the discobox or here, on this machine, handed the
discobox. Tools are declared, the last one winning on a shared name, by:

  this CLI                            vscode, zed
  the discobox's image                /usr/local/share/discobox/tools
  the discobox's primary source       .discobox/tools
  you                                 <config dir>/discobox/tools

A declaration is a .yaml file naming the program it runs, or a script with a
front-matter block that is itself what runs. Only this CLI and you can declare
a tool that runs on this machine.

A script's front matter is a commented block between two "#---" lines:

  #!/bin/sh
  #---
  # name: tuicr
  # description: review the box's changes in tuicr
  # runs: host      here, on this machine; the default, sandbox, copies the
  #                 script into the discobox and runs it there
  #---

A key: line names one key that runs a tool from the console's tools picker.
The console runs a host tool with no terminal and shows only whether it
failed, so a key there suits a tool that opens a window of its own, such as an
editor; a terminal program, like this one, is run with "discobox tools tuicr".

The id is the file name without an ordering prefix or extension
(50-tuicr.sh is tuicr). A .yaml tool states the same fields as YAML, plus
program: and args:, whose {discobox.id}, {discobox.cli}, {discobox.server},
{discobox.project}, {ssh.host}, {ssh.url}, {git.url}, {workdir} and
{workdir.urlpath} are filled in.

A script that runs here is handed the discobox in its environment:

  DISCOBOX_ID        the discobox's ID
  DISCOBOX_WORKDIR   its working tree, inside the discobox
  DISCOBOX_SSH_HOST  an ssh_config host that reaches it
  DISCOBOX_SSH_URL   ssh://host/workdir
  DISCOBOX_GIT_URL   the same, for git; empty when it has no working tree
  DISCOBOX_CLI       this discobox binary
  DISCOBOX_SERVER    the server's address
  DISCOBOX_PROJECT   the project's ID

with DISCOBOX_IROH_RELAY_URLS set to what this CLI dials that server with,
and no DISCOBOX_TOKEN: a CLI is authorized by its connection to the server. A
.yaml tool has its placeholders instead and none of this environment, so an
editor's terminals are not aimed at one discobox for good.

DISCOBOX_CLI reads DISCOBOX_SERVER and DISCOBOX_PROJECT back, so whatever the
script runs it with reaches the same discobox, and the script can set the
discobox up from this machine before opening it, for example installing a
program there and copying your own config in. Copy config, never a program,
and never a credential: the discobox's agent reads whatever lands in it, so a
token or key belongs in "discobox secret", not in a copied file. A program is
wrong too: this machine may be macOS and the discobox Linux, on another
architecture. Have the discobox download the program itself, into ~/.cache,
which every discobox in the pool running as the same user ID shares, so the
download happens once. Because any of those can write there, other people's
included on a shared pool, pin the program's sha256 and run only a copy that
matches it: check the cached file before using it, download it again when it
does not match, and copy it into the discobox's own ~/.local/bin, checking the
copy, never running or linking the cached file itself:

  db() { "$DISCOBOX_CLI" "$@"; }
  db exec "$DISCOBOX_ID" -- sh -s <<'IN_BOX' || exit   # a refused install stops
    set -e
    case $(uname -m) in    # sha256 of the tuicr binary in each release tarball
      x86_64)  sum=7fd209205bdc3e682438f0f0d81684fb76de9f49e3b45feca36dde0488dd7f9c ;;
      aarch64) sum=fad52a20f425af50be5fb51554a6460cc044341ada5b7b3fdaf8b09ecf82cf1d ;;
    esac
    ok() { echo "$sum  $1" | sha256sum -c --status; }
    c=$HOME/.cache/discobox-tools/tuicr/0.28.0
    ok "$c/tuicr" || { rm -rf "$c" && mkdir -p "$c" && curl -fsSL \
      "https://github.com/agavra/tuicr/releases/download/v0.28.0/tuicr-0.28.0-$(uname -m)-unknown-linux-gnu.tar.gz" |
      tar -xzf - -C "$c"; }
    mkdir -p ~/.local/bin ~/.config
    n=~/.local/bin/.tuicr.new
    cp "$c/tuicr" "$n"; ok "$n" || { rm -f "$n"; exit 1; }
    mv "$n" ~/.local/bin/tuicr
    rm -rf ~/.config/tuicr
  IN_BOX
  db cp -r ~/.config/tuicr "$DISCOBOX_ID:.config/tuicr"
  exec "$DISCOBOX_CLI" exec "$DISCOBOX_ID" -- tuicr "$@"

A script that runs here must be executable (chmod +x); it is run by its
shebang, and the arguments after DISCOBOX are its "$@". Everything after
"exec DISCOBOX --" runs in the discobox, in the working tree, with
~/.local/bin on its PATH, and with a terminal when this one is; a ~ or $HOME
there is expanded here, by this script's shell, so quote it into an "sh -c"
when it means the discobox's. Paths "discobox cp" is given in a discobox are
relative to its user's home, and it copies the way scp does: into a directory
that exists, so remove the old copy first. A program that asks before it
installs has no terminal to ask on under "sh -s". Run "discobox tools ls" to
see the new tool, and why it cannot run if it cannot.
~~~~

```text
discobox tools TOOL [DISCOBOX] [--] [ARG...] [flags]
```

## discobox wait

~~~~text
Wait until something happens in a discobox's terminal, and say what.

UNTIL is one of:
  blocked[:KIND]   the agent is waiting on a person (KIND: permission, question, auth)
  finished         the agent ended its turn
  idle[=DURATION]  no output or input for DURATION (default 5s)
  exit             the terminal's program exited
  HOOK             a harness hook, such as Stop or Notification (hook:NAME
                   for a hook named like one of the words above)

blocked and finished are what the agent reports of itself; a harness that
reports nothing is waited on by a HOOK, idle or exit. Repeat --until to wait
for whichever comes first. By default only what happens after the last input
sent to the terminal counts, so "send" then "wait" never misses the answer.
Without --for, wait has no time limit; with it, wait exits 124 when DURATION
passes. It prints what held, then the point a later --after resumes from.
~~~~

```text
discobox wait DISCOBOX [flags]
```

Examples:

```text
  discobox send mybox 'run the tests again' && discobox send-key mybox Enter
  discobox wait mybox --until finished --until blocked
  discobox wait mybox --until idle=10s --for 5m || echo timed out
  discobox send-key mybox C-c
```

| Flag | Type | Default | Description |
| --- | --- | --- | --- |
| --after | string |  | count only what happens after resume &#96;POINT&#96; |
| --color | WHEN | auto | set color &#96;WHEN&#96; to auto, always, or never |
| --debug | bool | false | print HTTP requests and the git commands run on this machine Value when passed without an argument: true. |
| --for | duration | 0s | give up after &#96;DURATION&#96; |
| --help, -h | bool | false | help for wait Value when passed without an argument: true. |
| --output, -o | string | table | output &#96;FORMAT&#96;: table or json |
| --server | string |  | connect to &#96;SERVER&#96;, an endpoint or a registered server's name; defaults to the primary "discobox admin remote primary" set, and to the local server when none is |
| --terminal, -t | string | primary | use &#96;TERMINAL&#96; |
| --token | string |  | bearer &#96;TOKEN&#96; for API requests |
| --until | stringArray | [] | wait for &#96;UNTIL&#96; (repeatable) |
