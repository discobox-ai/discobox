# secrets review notes

- A rule answers, is proposed from, and is made from only a request that carries a policy: `ruleTestable`, `ruleProposable`, and the console's `CredentialRequest.Ruleable` say so together, and change together. A rule's policy is what a request's is held to, so a request with uses alone has nothing to hold.
- A rule's policy is compared with `policy.Within`, both sides resolved for the discobox that asked, and only `Unsettled` conditions reach the judge. Never put a whole policy, or a statement code found outside the rule, to the judge: a model asked "is this within" of a list leaks across items (ADR 26-10-20-782, Context). A rule never records resolved values; one that did would bind every later discobox to the first one's repository.
- The grant a rule mints carries the request's policy as asked, held to the values it resolved to when it was compared (`approvalWrite.shown`), never the rule's class.
- A policy handed on by a discobox goes through `delegationCovering`, on every path that hands one on — an approval and a create, and the create's transaction holds it to the same delegation's policy again (`heldDelegation`). Uses are never judged against a delegation's: a check that reads them in place of the policy hands on whatever policy came with them.
- Every grant with uses carries a policy, and only such a grant does (`guardPolicy`, in `mintGrantAs` and `PrepareSandboxGrants`). A new path that builds a grant without either goes through it too.
- Every field of a grant a rule mints is authorization somewhere downstream, so each must be one the rule held. A rule holds a request's policy, never its uses, and approves no delegation (`checkRule`, `ruleProposable`, `ProposeApprovalRuleFromGrant`, the console's `Ruleable` and its grant card) until ADR 26-10-22-689's Deferred is decided. Before lifting it, check nothing else reads a rule-minted grant's uses as authorization.
- A grant a discobox hands on records the delegation it was made under (`SecretGrant.DelegationID`), set where the hand-off mints — `commitApproval` and `PrepareSandboxGrants`. Code settles most hand-offs with no judge, so no verdict names the delegation; a new path that hands a grant on and leaves it empty leaves that grant untraceable to what allowed it.
